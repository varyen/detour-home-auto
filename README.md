# WG Home Auto

Android-приложение, которое **автоматически выключает VPN WireGuard в домашней Wi-Fi сети и включает его во всех остальных случаях** (другая Wi-Fi, мобильный интернет, отсутствие сети).

Управление настоящим тоннелем происходит через официальное приложение **WireGuard** — наше приложение шлёт ему команды. Своего VPN-движка внутри нет.

---

## Как это работает

1. Foreground-сервис постоянно слушает смену Wi-Fi через `ConnectivityManager.NetworkCallback`.
2. При каждом изменении читается SSID текущей сети.
3. Если SSID есть в списке «домашних» → отправляется `SET_TUNNEL_DOWN` (VPN выключается).
4. Иначе (чужая сеть / мобильный интернет / нет Wi-Fi) → `SET_TUNNEL_UP` (VPN включается).
5. Команды идут broadcast-Intent'ом приёмнику `com.wireguard.android/.model.TunnelManager$IntentReceiver`
   (action `...SET_TUNNEL_UP` / `...SET_TUNNEL_DOWN`, extra `tunnel` = имя тоннеля).

---

## Требования

- Android 8.0+ (проверялось под Android 12+), `minSdk 26`, `targetSdk 34`.
- Установленное **официальное приложение WireGuard** с хотя бы одним настроенным тоннелем.

---

## ⚙️ Обязательная настройка WireGuard (без неё команды игнорируются)

В приложении **WireGuard**:

1. Меню (☰) → **Settings** (Настройки) → **Advanced**.
2. Включите **«Allow remote control apps»** (Разрешить приложениям удалённое управление).

> Это ключевой шаг. Исходный код WireGuard явно проверяет этот флаг и молча отбрасывает
> внешние команды `SET_TUNNEL_UP/DOWN`, если он выключен.

Запомните **точное имя тоннеля** (регистр важен) — его нужно будет ввести в нашем приложении.

> Совет: если команды не срабатывают, переустановите WG Home Auto **после** установки WireGuard —
> так системное разрешение `com.wireguard.android.permission.CONTROL_TUNNELS` гарантированно выдаётся.

## Использование

1. Откройте **WG Home Auto**.
2. В поле **«Тоннель WireGuard»** введите имя тоннеля точно как в WireGuard.
   - Имя проверяется по правилам WireGuard (1–15 символов: латиница, цифры, `_ = + . -`).
   - Нажмите **«Проверить (включить тоннель)»** — если имя верное, тоннель поднимется в WireGuard.
     *(Список тоннелей WireGuard не отдаёт сторонним приложениям — ни через ContentProvider,
     ни ответным broadcast, — поэтому имя вводится вручную и проверяется этой кнопкой.)*
3. Подключитесь к домашней Wi-Fi и нажмите **«Добавить текущую сеть»** (можно добавить несколько сетей).
4. Включите **«Автоматический режим»**.
   - Приложение запросит доступ к **геолокации** (нужен для чтения имени Wi-Fi — требование Android)
     и к **уведомлениям** (Android 13+).
   - ⚠️ На Android 12+ обязательно выберите **«Точное»** (Precise), а не «Приблизительное», и включите
     службы геолокации в системе — иначе SSID читаться не будет.

В блоке **«Статус»** видно: текущую сеть, домашняя она или нет, целевое состояние VPN и состояние службы.

## Разрешения — зачем каждое

| Разрешение | Зачем |
|---|---|
| `ACCESS_FINE_LOCATION` | Android отдаёт SSID Wi-Fi только приложениям с точной геолокацией |
| `FOREGROUND_SERVICE` + `..._LOCATION` | Постоянный мониторинг в фоне (сервис типа `location`) |
| `POST_NOTIFICATIONS` | Постоянное уведомление службы (Android 13+) |
| `RECEIVE_BOOT_COMPLETED` | Возобновление мониторинга после перезагрузки |
| `com.wireguard.android.permission.CONTROL_TUNNELS` | Право отправлять команды приложению WireGuard |
| `ACCESS_WIFI_STATE`, `ACCESS_NETWORK_STATE` | Чтение состояния сети |

## Сборка и установка

### Вариант A — Android Studio (проще)
Открыть папку проекта в Android Studio → дождаться Gradle Sync → **Run ▶**.

### Вариант B — командная строка (Windows / PowerShell)
```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
cd c:\www\vTools
.\gradlew.bat :app:assembleDebug
```
Готовый APK: `app\build\outputs\apk\debug\app-debug.apk`

Установка на подключённый по USB телефон (с включённой отладкой по USB):
```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## Как протестировать

1. Настройте тоннель в WireGuard и включите «Allow remote control apps».
2. В WG Home Auto: укажите имя тоннеля, добавьте домашнюю сеть, включите автоматический режим.
3. Находясь дома → в WireGuard тоннель должен стать **выключенным**.
4. Отключите Wi-Fi (или выйдите из зоны) → тоннель должен **включиться** сам.
5. Логи для диагностики:
   ```powershell
   adb logcat -s MonitorService WireGuardController
   ```

## Защита от утечек трафика

Тумблер **«Защита от утечек»** (по умолчанию включён) сокращает окно, в котором трафик мог бы уйти
мимо VPN на переходе между сетями. В строгом режиме VPN включается, даже пока вы формально дома, если:

- **уровень сигнала слабый** — RSSI ниже порога (гистерезис: надёжно при ≥ −70 dBm, ненадёжно ниже −80 dBm);
- **Wi-Fi без реального интернета** (`NET_CAPABILITY_VALIDATED = false`).

Плюс переключение асимметрично: **включение VPN ~0.7 c** (быстро), **выключение ~4 c** (чтобы не мигал).

> **Полная гарантия против утечек** — только встроенный kill-switch WireGuard:
> Настройки Android → Сеть → VPN → WireGuard → «Всегда включён» + «Блокировать соединения без VPN».
> Но он блокирует трафик и дома тоже, поэтому несовместим с задачей «дома напрямую». Это компромисс:
> либо прямой доступ дома с крошечным окном утечки на переходе, либо zero-leak ценой блокировки без VPN.

## Ограничения и заметки

- **Агрессивная экономия батареи** (Xiaomi/MIUI, Huawei, Samsung и др.) может убивать фоновый сервис.
  Отключите оптимизацию батареи для приложения (кнопка «Разрешения приложения» → сведения о приложении).
- Матч идёт по **имени сети (SSID)**. Если несколько разных сетей имеют одинаковое имя, они считаются одной.
  (Матч по конкретной точке BSSID можно добавить позже.)
- Между сменой сети и переключением VPN есть небольшая задержка (~1.5 c, антидребезг).
- Приложение не «воюет» с ручным управлением: оно реагирует только на события смены сети.

## Структура проекта

```
app/src/main/java/com/vtools/wghome/
  MainActivity.kt        — UI на Jetpack Compose + запрос разрешений
  MonitorService.kt      — foreground-сервис, NetworkCallback, логика вкл/выкл
  WireGuardController.kt  — отправка команд в WireGuard (broadcast-Intent)
  WifiUtils.kt           — чтение текущего SSID
  SettingsRepository.kt   — настройки (SharedPreferences)
  AppState.kt            — живой статус для UI
  BootReceiver.kt        — автозапуск после перезагрузки
```
